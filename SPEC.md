# Selectable cooperative delivery

Repeated consumed phases must verify their immutable snapshot and refuse a
changed current receipt with fresh-assignment guidance. An earlier input
duplicate after its later final must preserve both phases. A crash-stranded
private snapshot may be reused only for identical bytes before DB commit;
conflicting/corrupt/nonprivate evidence stays untouched and refused.

Provide a bounded read-only direct-owner recovery view after expiry: distinguish
reported final/input, snapshot integrity/orphans, unrelayed fact counts and
unknown delivery. It must not claim objective/turn completion, infer approval,
renew, replay, send, steer or park tasks. Root sees coordinator summaries, not
a recursive child-chat scan. No live installation follows from source fixes.

An explicitly named coordinator may own future registrations for a bounded
direct worker group after official saved-project and execution-cwd verification.
Keep existing assignments unchanged, one owner per assignment and one layer
below the fixed root. The same watcher batches by owner. Capture fingerprinted
facts in the report transaction; coordinator judgment is a separate artifact.
Relay verified facts once to the fixed parent. No subtree scans, model polls,
automatic spawning/approvals or lease extension. Withdrawal changes future
registrations only. Real nested delivery requires separate receiving-turn proof.

Latest human choice explicitly accepts visible watcher messages and requests
restoration. Preserve the uncommitted record-only/on-demand work as the default
mode; visible delivery requires explicit opt-in at the current valid lease.
Do not use hidden hooks/private APIs or claim free receiver wakes.

The earlier outbound job was unloaded. Update its producer path compatibly,
then activate a new guarded visible service only after independent review.
Capture MAX(event.rowid) and activation time atomically; qualify only later
fresh pending reports. Never replay previously surfaced, old pending, quiet-
period, claimed/failed/uncertain records, or extend expiry. No worker reacks.

Preserve exact registered runtime identities, immutable snapshots, independent
input/final phases, durable deduplication, and an unused later final after input.
Coalesce readiness for20seconds and urgent input/failure for2seconds using
deterministic checks, at most64assignments per batch. Keep phases together;
retain every event even when headline uses its newer final status.

Commit immutable private index and all member claims before one native queue
attempt without --resume. Unknown outcomes remain sticky, never blindly retry.
Visible message: counts and one short inbox pointer, no worker prose/full ids/
hashes. Index lookup verifies membership, exact worker/assignment/phase and
original receipt hashes. No automatic approvals, dispatch or archival.

Record-only and on-demand inbox remain available without model calls or
consuming events. Main model/context usage occurs only on a delivered notice;
no percentage claims. Preserve separately scoped hourly background fallback.

Proof: fake-queue regression for quiet/default and explicit visible modes,
cutoff/history/expiry preservation, burst/priority/no lost final, index integrity,
concurrent claims and sticky failure/crash. Independent targeted messaging/
lifecycle review. Verify actual new mode, service/process and source fingerprint;
one fresh useful restoration-result notice may prove delivery, never repeated
synthetic probes. Retain exact rollback/status and original finite enrollment.
